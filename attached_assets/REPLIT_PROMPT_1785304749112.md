# Build prompt — Halo Property Operations Kanban

Paste everything below into Replit AI as a single prompt. It is a complete
specification: every colour, dimension, template, interaction, animation and

## 0 · What you are building

A single-page property-management operations board for **Halo** (brand: Halo /
Archangel Contracting Services). One property: **Northgate Commons, 412 units,
Prosper TX**. A property manager lives in this screen all day.

It has three surfaces on one scrolling page:

1. **App chrome** — sticky header, live Pulse rail, lens/filter toolbar, bulk-selection bar
2. **The board** — six columns of cards (or a site-map view)
3. **The card library** — all 22 card templates below the board

Plus five overlays: command palette, rapid triage, card detail drawer, crew GPS
map, export dialog.

**Non-negotiable:** every card is exactly **340 × 430 px**. Not min-height, not
flex-grow — a fixed frame with fixed internal region heights and clipped
overflow. A card with more to say summarises harder. This is the core idea; if
cards vary in height the build is wrong.

## 1 · Stack

- Vanilla React 18 via CDN + Babel standalone, or Vite + React. No component library, no Tailwind.
- **All styling is inline style objects.** No CSS files, no classes. The only global CSS is: `@font-face`/font link, `body` reset, `::selection`, `:focus-visible`, scrollbar styling, and four `@keyframes`.
- Express server (`server/index.js`) serving `public/` and exposing the action API in §10.
- Node 20. `npm start` runs the server on `0.0.0.0:$PORT || 3000`.

```
server/index.js        express: static + /api/actions + /webhooks/halo
public/index.html      landing
public/board.html      the app
src/actions.js         action registry (§10)
src/templates.js       the 22 templates (§7)
src/engine.js          dispatch(): guard → API call → events → automations
src/hooks.js           event bus
src/handlers.js        integration stubs
```

## 10 · Automations — every button emits a named action

Each control resolves to exactly one action id. The UI emits
`window.dispatchEvent(new CustomEvent('halo:action', { detail: evt }))` and calls
`window.HALO.dispatch(evt)` when present; a bridge script POSTs to
`/api/actions`.

```jsonc
{
  "id": "evt_...", "action": "ap.approve_invoice",
  "occurred_at": "ISO-8601",
  "actor":    { "role": "manager", "name": "Dana Okafor", "id": "usr_dokafor" },
  "property": { "id": "prop_northgate", "name": "Northgate Commons" },
  "payload":  { "card": { "card_id": "INV-2196", "template": "invoice", "category": "money",
                          "unit": "A-307", "stage": "Coded", "stage_index": 1,
                          "pipeline": ["..."], "owner": "AP Queue",
                          "sla_minutes_remaining": 900, "lane": "triage" } }
}
```

**Universal:** `card.opened`, `card.export_requested`, `card.stage_advanced`
(payload adds `from_stage`, `to_stage`, `automations[]`), `card.moved`
(`from_lane`, `to_lane`, `method:"drag"`).
**Bulk:** `bulk.export_requested`, `bulk.advance_stage`, `bulk.assign`, `bulk.defer`.
**Triage:** `triage.approve`, `triage.assign`, `triage.defer`.
**Crew:** `crew.locate_requested` (payload carries name, badge, status, gps,
accuracy, last ping, geofence, clock in/out, units),
`maint.work_order_created_from_finding`, `vendor.job_report_opened`.

**Per template, primary / secondary:**

Each action declares an HTTP method, a Halo endpoint, a payload builder, the
events it emits, whether it advances the stage, and an optional **guard** that
blocks it with a reason:

- `ap.approve_invoice` — blocked unless the three-way match passes
- `ap.release_payment_run` — blocked without owner approval
- `vendor.approve_change_order` — blocked above $5,000 without owner sign-off
- `vendor.signoff_job` — blocked with zero after-photos
- `compliance.dispatch_and_file_packet` — blocked on an incomplete evidence packet
- `leasing.send_renewal_offer` — blocked while work orders are open
- `leasing.generate_deposit_statement` — blocked unless photos are paired per charge
- `maint.defer_pm` — blocked when deferral voids the warranty inside 30 days

**Stage automations.** Advancing fires the template's `onEnter` list for the new
stage, shows them in the auto-triggered strip, and emits them on the bus. E.g.
work order → Dispatched fires `sms.resident.window` + `tech_app.push`; crew →
Signed Off fires `report.generate`, `access.revoke_credentials`,
`ap.invoice_expected`; invoice → Approved fires `ap.queue_for_run` + `notify.vendor`.

**Escalate-from-card.** On the vendor crew card, each finding row's ESCALATE
control creates a real work-order card in the Signal column (title = the finding,
unit = the finding's unit, SLA 240m for HIGH / 1440m otherwise, owner Marcus
Webb, linked back to the job), removes the finding from the source card, emits
`maint.work_order_created_from_finding`, and toasts the new id.

## 11 · State and behaviour

- One card record: `{ id, template, category, code, unit, title, subtitle, lane, stageIndex, stages[], slaTarget, minutesRemaining, owner, building, selected, showNext, payload }`.
- **Keep one `elapsed` counter in state and derive every clock from it.** Tick every 30 seconds. Never rebuild the card array on a tick.
- **Cache per-card event handlers by card id** so unchanged cards keep referential equality and skip re-render.
- Role switch filters which categories are visible: Manager sees all; Tech sees maintenance, access, vendor; Vendor sees vendor, compliance, money.
- Escape closes every overlay. `⌘K`/`Ctrl+K` opens the palette from anywhere.
- Toasts are navy pills at the bottom centre, 2.6s.
